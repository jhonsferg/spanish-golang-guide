# Go 1.19 (agosto 2022)

Versión de consolidación tras los generics de 1.18: casi sin cambios de
lenguaje, pero con una pieza clave para producción - el **soft memory
limit** - y tipos atómicos por fin ergonómicos.

## Cambios de lenguaje

- Un único cambio: corrección del scope de los parámetros de tipo en
  declaraciones de métodos (issue #52038). Sin impacto práctico en la
  mayoría del código.

## Runtime y garbage collector

- **Soft memory limit**: `runtime/debug.SetMemoryLimit()` o la variable
  `GOMEMLIMIT` permiten fijar un límite blando de memoria (heap de Go +
  memoria gestionada por el runtime). Funciona junto a `GOGC` - respeta el
  límite incluso con `GOGC=off` - y limita el CPU dedicado a GC al 50% para
  evitar *GC thrashing*.
- Menos goroutines de GC ejecutándose en threads idle.
- Asignación inicial de stacks basada en el uso histórico promedio, evitando
  crecimientos tempranos innecesarios.
- En Unix, el límite de descriptores de archivo abiertos (`RLIMIT_NOFILE`)
  se sube automáticamente al máximo permitido.

## Herramientas

- `-trimpath` ahora aparece en los build settings (visible con
  `go version -m`).
- `go test` y `go generate` anteponen `GOROOT/bin` al `PATH`.
- `go list -json` acepta una lista CSV de campos para reducir el output.
- **Doc comments**: soporte para enlaces, listas y encabezados; `gofmt`
  reformatea comentarios de documentación; nuevo paquete `go/doc/comment`.
- **vet**: nuevo check `errorsas` - detecta `errors.As()` con segundo
  argumento de tipo `*error`.
- Nueva build constraint `unix` reconocida en `//go:build`.
- **Compilador**: jump tables para switches grandes (~20% más rápido en
  amd64/arm64).

## Librería estándar

**`sync/atomic` - nuevos tipos atómicos**

```go
atomic.Bool, atomic.Int32, atomic.Int64,
atomic.Uint32, atomic.Uint64, atomic.Uintptr, atomic.Pointer[T]
```

Ocultan el valor subyacente forzando el uso de las APIs atómicas; `Int64`/
`Uint64` quedan auto-alineados a 64 bits incluso en sistemas de 32 bits.

**Seguridad**

- `os/exec.Command` y `LookPath` ya **no permiten** búsquedas relativas al
  directorio actual - cierra una clase de vulnerabilidad clásica en
  Windows/Unix.
- `crypto/elliptic`: operar sobre puntos inválidos ahora hace panic.
- `crypto/x509`: `CreateCertificate` rechaza `MD5WithRSA` y números de serie
  negativos.

**Otras adiciones**

| Paquete | Cambio |
|---|---|
| `fmt` | `Append()`, `Appendf()`, `Appendln()` |
| `net/http` | 1xx informational headers; `MaxBytesReader` retorna `MaxBytesError` |
| `net/url` | `JoinPath()` y método `URL.JoinPath()` |
| `sort` | `Find()` como alternativa más simple a `Search()` |
| `time` | `Duration.Abs()`, `Time.ZoneBounds()` |
| `flag` | `TextVar()` para flags con `encoding.TextUnmarshaler` |
