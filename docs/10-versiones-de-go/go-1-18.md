# Go 1.18 (marzo 2022)

La versión que redefinió el lenguaje: introduce **generics**, fuzzing
integrado, workspaces multi-módulo y el paquete `netip`. Es el punto de
partida razonable para cualquier repaso "de qué trata el Go moderno".

## Cambios de lenguaje

- **Generics**: implementación completa de parámetros de tipo para funciones
  y tipos. Nuevo token `~` para especificar el tipo subyacente en
  constraints. Las interfaces pueden contener tipos arbitrarios (no solo
  métodos) y elementos unión.
- Nuevos identificadores predeclarados: `any` (alias de `interface{}`) y
  `comparable` (constraint para tipos comparables con `==`/`!=`).
- Paquetes experimentales de apoyo: `golang.org/x/exp/constraints`,
  `golang.org/x/exp/slices`, `golang.org/x/exp/maps`.
- Corrección de bugs del compilador: reporte correcto de variables no usadas
  dentro de function literals, y de overflow en constantes rune.

## Runtime y garbage collector

- El GC incluye el trabajo no-heap (stack scanning) al calcular la
  frecuencia de ejecución, dando un comportamiento más predecible.
- El runtime retorna memoria al sistema operativo de forma más eficiente.
- Mejor precisión en stack traces (marca con `?` valores potencialmente
  inexactos).
- Fórmula de crecimiento de slices en `append` mejorada.

## Herramientas

- **`go get`**: deja de construir/instalar binarios; ahora solo ajusta
  `go.mod`. Para instalar, usa `go install example.com/cmd@latest`.
- **`go work`**: nuevo modo *workspace* multi-módulo con archivo `go.work`.
- **Fuzzing**: flags `-fuzz`, `-fuzztime`, `-fuzzminimizetime` en `go test`.
- **`go build -asan`**: soporte para address sanitizer.
- **gofmt**: lee y formatea archivos en paralelo, notablemente más rápido en
  máquinas multi-CPU.
- **vet**: soporte para código genérico; mejoras en `copylock`, `printf`,
  `sortslice`, `testinggoroutine`, `tests`.
- **Compilador**: paso de argumentos y resultados por registros en arm64,
  ppc64 y x86 (más rápido en runtime, ~15% más lento al compilar por el
  costo de generics). **Linker**: muchas menos relocaciones → linking más
  rápido y binarios más pequeños.

## Librería estándar

**Nuevos paquetes**

- `debug/buildinfo`: acceso a versiones de módulos, VCS y flags de build
  embebidos en un binario.
- `net/netip`: tipos `Addr`, `AddrPort`, `Prefix` — inmutables, comparables
  y eficientes en memoria (allocation-free I/O).

**Cambios notables**

| Paquete | Cambio |
|---|---|
| `crypto/tls` | TLS 1.0/1.1 deshabilitados por defecto en clientes (`MinVersion` → TLS 1.2); certificados con SHA-1 rechazados |
| `crypto/elliptic` | P224, P384, P521 hasta 4x más rápidos |
| `strings`, `bytes` | Nuevo `Cut()`; `strings.Clone()`; `Trim*` sin allocations (~10x más rápido) |
| `reflect` | `Value.UnsafePointer()`; renombrados `Ptr`→`Pointer`, `PtrTo`→`PointerTo` |
| `sync` | `Mutex.TryLock()`, `RWMutex.TryLock()`, `RWMutex.TryRLock()` |
| `testing` | Nueva `testing.F` para fuzzing |

## Fuzzing

Implementación completa de fuzzing integrado en el toolchain, con la interfaz
`testing.F` y soporte nativo en `go test`.
